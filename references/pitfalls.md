# 坑全清单（基准卷 lvse 实证，症状→根因→根治→验证四件套）

> 编号 1-17；坑 1-11 与 docx-quota-extract 坑 25-34 同源（lvse 提炼），坑 12-17 来自 sz11 第二卷实战（2026-10-15）。

## 一、转换层（阶段 0）

### 坑 1｜pymupdf4llm import 即段错误
- **症状**：`import pymupdf4llm` 段错误（exit 139，1.28.2 layout 引擎）。
- **根因**：布局引擎 C 库与运行环境冲突（pymupdf 本体不受影响）。
- **根治**：转换层用裸 fitz 自研（字号分级 + find_tables）。
- **验证**：269 页全转，md 字节级可复现。

### 坑 2｜旋转水印 redact = 整页抹除
- **症状**：对 ~40° 旋转水印行 bbox 做 redact → 整页内容塌缩。
- **根因**：旋转文本 bbox 是旋转外接矩形，轴对齐化后罩全页。
- **根治**：不 redact；单元格级**行首**孤立 token 剔除 `^([水印字符集])\s`——行首锚定防「基价」等双面字误伤。
- **验证**：水印字符零泄漏进表行；「基 价(元)」等正常术语无损。

### 坑 3｜E-BZ 页码散字：单字符行 + 外侧边 + 分区 offset
- **症状**：页码提取 0 命中或数字倒序（'942'≠'249'）。
- **根因**：西文嵌入字体基线下沉致页码每字符独立成行；位置在**外侧边**（偶页左 x≈50、奇页右 x≈510），居中假设错误；目录区与正文区 offset 不同。
- **根治**：y 带 + 外侧边 x 双条件收集散字，**按 x 左→右重组**（禁 reverse）；offset 分区标定；无页码扉页对排除。
- **验证**：页锚 258/269；扉页对（12/13、66/67…）正确排除。

## 二、md 解析层（阶段 1-2）

### 坑 4｜章标题 `# ` 前缀剥离 → startswith("#") 判界静默全失效
- **症状**：册说明 buf 吞掉 848 段落；所有文本前缀判界静默失效（不报错、产物悄悄错）。
- **根因**：extract_md 产块时剥掉 md 标题前缀存 text，下游沿用文本前缀判界。
- **根治**：块结构显式 `kind:"h1"/"h2"`，**全部边界检查改 kind 判定**。
- **验证**：册说明段落收敛至权威条数；章节区间全对。

### 坑 5｜md 合并单元格形态 ≠ docx 纵向合并
- **症状**：消耗行分类失败（kind 链断裂）；名称行/消耗行混淆；跨列标签留空。
- **根因**：docx 纵向合并读出**每行重复值**，md 合并单元格**只有首格有值**——两种 Office 形态语义不同。
- **根治**：行判别三法——①消耗行=c0 空+前 kind 链式；②名称行=r[1] 无值+r[3:] 非数字文本；③跨列标签 hfill 横向填充；费用行 `"(元)" in joined`；规格/档位行放行。
- **验证**：487 子目 parse_issues=0，人材机消耗行全分类。

### 坑 6｜工作内容/计量单位拆行 → 双遍扫描
- **症状**：430 子目 unit 空（单遍扫到「工作内容」行即 break）。
- **根因**：docx 两者同段，md 拆成独立两行，单遍状态机被先出现的行截断。
- **根治**：unit/work 各扫一遍；分号结尾的「N.」子行是工作内容延续**不 break**。
- **验证**：unit/work 零空（门3 全绿）。

## 三、目录/条文层（阶段 7）

### 坑 7｜目录双栏重组（不经 md）
- **症状**：目录行错配/丢行/页码错挂。
- **根因**：双栏排版全文序输出左右栏交错；md 表格化破坏字符坐标。
- **根治**：从 nowm.pdf 目录页 dict 直接重建——x 分栏 + 栏内 y±6.5 聚类 + 长标题/页码行合并；页码字符坐标是唯一权威。
- **验证**：目录 N 行与正文集合全等、页码单调（门6）。

### 坑 8｜节标题折行污染 sections → 跟表验证
- **症状**：sections 32 个 vs 目录权威 14 个。
- **根因**：说明区长标题折行后恰命中节标题正则。
- **根治**：节标题判定加**跟表验证**（其后 6 块内须有表格）；窗口必须 6 块（4 块漏表距 5 块的案例）。
- **验证**：sections 与目录节行集合全等。

## 四、校验/前端层（阶段 6/9）

### 坑 9｜H1 恒等式项数因卷而异
- **症状**：H1 全卷 fail（曾 487/487 红）。
- **根因**：沿用三项式（基价=人+材+机），本卷实为**四项制含综合费**。
- **根治**：H1 公式**开工前用已知好卷样例校准**；「—」费项按 0 计并留痕；H2 费率带宽按卷实测。
- **验证**：H1 487/487（299 条「—」计 0 留痕）。

### 坑 10｜P1 灵活正则必须作用于未去空白原文
- **症状**：P1 44/487 fail——去空白后相邻编码粘连 '20-920-10'，lookbehind 误杀。
- **根因**：页文本 strip 后相邻子目编码拼接；E-BZ 数字间距又被随机空格拆开——两个方向同时破坏正则。
- **根治**：正则作用于**原始未去空白**页文本：编码 `(?<!\d)前缀-\s*N(?!\d)`、基价 `120[\s.]*78`（E-BZ 空格容忍）。
- **验证**：P1 487/487（对**官方带水印原版**取证——提取用 nowm 干净源、校验用官方原版，双源口径）。

### 坑 11｜前端契约错配致「加载中」假死 + 冒烟必须渲染级
- **症状**：成果库首页永远「加载中…」；文件存在、门控全绿（基线锚的就是错配版）。
- **根因**：两级——①build_front 产出 docx 短键契约 DATA，模板吃 PDF 长键契约（`DATA.stats.h`/`DATA.sections.some` 相继 TypeError，script 整体崩溃）；②冒烟只验文件存在未执行渲染。
- **根治**：①严格按 PDF 长键契约组装 DATA（见 pipeline 阶段 9 契约清单）；②渲染级冒烟机械化（smoke_front.mjs：启动链+13 视图路由真跑）。
- **验证**：冒烟 22/22；端到端字节级一致；九门 9/9。
- **纪律**：前端完成态=渲染级冒烟全绿；门控基线只锚「可复现」不锚「可渲染」。

## 五、流程纪律（管理类）

### 坑 12｜水印 Form XObject：删指令级（sz11 实证，坑 2 的根治升级）
- **症状**：字符级 redact 去水印必误伤（水印字符 bbox 与正文重叠，sz11 P11 目录页实证 `(52)→(52`、整行被抹）。
- **根因**：本批次官方 PDF（lvse/sz11 同源）的旋转水印封装在**独立 Form XObject**（如 Fm0，内容流仅 `/SimHei 36 Tf` + 单 Tj），主内容流仅一条 `/Fm0 Do` 引用。
- **根治**：`re.sub(rb"/Fm0\s+Do\s*", b"", cs)` 删指令=**物理隔离零误伤**；逐页对账（删除前后非旋转文本字节级一致，任一页不一致即中止）+ 全书终验残留=0。
- **验证**：sz11 245/245 页零误伤。**比坑 2 的"行首 token 剔除"更优**——有 XObject 形态优先走本坑，无 XObject 才退坑 2。

### 坑 13｜章码≠章序 + 章码重复 + 目录/正文章码不一致（sz11 实证）
- **症状**：①二三四章**共用 041102**；②第六章目录印 041105、正文印 041106；③按章码字符串匹配节行 → 断链（22 子目无 node_id）。
- **根因**：官方排印的章码是"编码体系位"不是"序号位"——重复/错位是书印事实，且目录与正文各自印刷可能不一致。
- **根治**：①章判别逐章**物理锚定**（按 h1 块位置切，禁按章码聚合）；②**节行按「目录章序」归章**（章行依序出现=序号 1..N，建立 order→章 code 映射），禁章码字符串匹配；③排印不一致留痕进 issues 不静默修正。
- **验证**：sz11 470 子目全部归属（44 节点）；门6 节名 ⊆ 目录节行全等。

### 坑 14｜书印无「工作内容」行 → 门3 断言语义（sz11 实证，**曾误诊为 SEC_RE 截断**）
- **症状**：work 空 18 条。曾误判为「表前『N. 名称』行被 SEC_RE 截断」——修正 SEC_RE 前后数字**不变**，证明非真因（回溯先遇「工作内容」段即 break，根本到不了名称行）。真因：**书印即无**（临时建筑/混凝土外加剂等组从「计量单位」直接进表）。
- **根治**：①定性靠证据——抽查缺work子目的 md 原文上下文，书印无该行=事实（留痕，不硬造，坑 20 同源精神）；②门3 断言改为本卷实测值+口径注释（`n_work == 18` 带「书印事实」说明）；③抽查脚本字段名先对 schema（items.json 是 list+字段 `work`，用错字段名会造出"全缺"假象——sz11 实证乌龙）。
- **验证**：18 条全部书印无该行（md 原文逐条目检）；门3 PASS 带留痕口径。

### 坑 15｜换参机械化的三类系统性漏网（sz11 实证，**积分消耗大头**）
- **症状**：换参后首跑连环炸——CODE_RE 漏换（codes 空）、三处路径漏换（Downloads/out_md 逐个 FileNotFoundError）、smoke 路由假绿（12001→041101 语义错位）。
- **根因**：①映射表写 `r"20-\\d{1,3}"` 双反斜杠形态，文件里是单反斜杠字面量 `20-\d{1,3}`——**永不命中且不报错**；②映射只换文件名不换目录（Downloads/nowm.pdf）；③**短码体系**（章码[2:] 如 041101→1101）在换参时被当全码映射（12001→041101），冒烟路由渲染空页也 PASS=假绿。
- **根治（机械手段，防"下次注意"）**：新增 `scripts/preflight_check.py` 开工自检——路径存在性全查、编码/章码正则对 md 源试命中（0 命中即红）、章码[2:]短码路由核对、守卫集成跑一遍、断言占位扫描。**换参后先跑 preflight 再进管线**，把 10+ 轮调试往返压到 1 轮。
- **验证**：sz11 复盘——三类漏网均可在 preflight 一轮内暴露。

### 坑 16｜页码带/单位白名单先实测再定参（sz11 实证）
- **症状**：页码 y 带 340-375 搬 lvse 参数首跑 0 命中（sz11 页码 y=350.4 精确）；H5 白名单三轮才补齐（漏 10台次/台次，再漏 10个）。
- **根治**：①页码标定**先抽样打印页脚 y 分布**再定带（禁直接搬上卷参数）；②H5 前先 dump 全库 unit 分布，一次性补齐本卷单位全集（措施项目特性：台·天/座·天/架次/次/10延长米堰体/100m3空间体积/10t金属设备 等）。
- **验证**：sz11 终态 H5 fail=0、页码三区段恒定 offset+13。

### 坑 17｜finalize 嵌核验数字 → 顺序依赖（sz11 实证）
- **症状**：端到端重跑后 db 字节失配；单跑 finalize 三连测却稳定。
- **根因**：finalize 嵌入 cost_check_report 的动态数字（H5 白名单修正期间核验数字在变）——db 内容依赖上游核验报告版本。
- **根治**：收官固定顺序 **finalize→cost_check→（参数变更后）再 finalize**→build_front；或 finalize 不嵌核验中间态。
- **验证**：固定顺序后九门全绿+复现验证通过。

### 坑 36｜窄表编码在 r[1] → 宽表搜索漏抓整表（az09 实证）
- **症状**：解析层报「无定额编号行」，措施项目类子目（9-282~286）整表消失，后续编号断档。
- **根因**：单/双子目窄表仅 2-3 列，编码在第 2 列 r[1]（清单编号/项目名称合并列），原代码行搜索只扫 r[3:]（宽表形态假设）。
- **根治**：代码行搜索加窄表回退——`len(r) > 1 and CODE_RE.match(cellname(r[1]))` 即认定（清单编号行不会匹配 9-N 全码形态，无误伤）。
- **验证**：az09 9-1~9-286 连续 0 issues。

### 坑 37｜视觉行左右分块 → 纯 y 排序颠倒（az09 实证）
- **症状**：19 条 work 截断 + 3 条缺单位（9-207/208/209），表现零散无规律。
- **根因**：convert 层纯按 y 稳定排序，但同一视觉行的左右分块 y0 相差 ~1.1pt（P26 实证：左「…水压试验、水」y=46.7 / 右「计量单位:10m」y=55.7 与「冲洗。」y=56.8 同视觉行），右段（续行/单位行）被插到左段与下一行之间，阅读顺序颠倒。
- **根治**：convert 元素排序改视觉行聚簇——y 差 ≤3pt 聚为同簇、簇内按 x 排序（正常行距 ≥10pt 不受影响）。
- **验证**：work 截断 0、缺单位 0。

### 坑 38｜计量单位挂续行尾部（az09 实证）

- **验证**：az09 单位缺失 0（与坑37 叠加根治）。

### 坑 39｜目录缺章标题行 → 全章下级行错挂（az09 实证）
- **症状**：前端节点树 ch2 无节、ch1 混入 ch2 节；子目章归属整体偏移。

- **验证**：az09 目录 101 行、6 章归属性 0 错挂；第二章子目 47 条全部回位。

### 坑 40｜附录标记误触 → 全书子目表变附表（az09 实证）
- **症状**：附表组首跑 0 条；放宽检测后二跑 53 条（全误）——P20 之后所有子目表被判附表。

### 坑 41｜章无「一、」式节行 → 回退其他行构造节节点（az09 实证）
- **症状**：冒烟「N 子目全部有 node_id 归属」fail——5 条系数计取项（9-282~286）无节点，前端树中不可达。

- **验证**：冒烟 24/24，节点 48→49，286 子目全归属。

## 六、流程纪律（管理类）

- 校核≠重做；疑点留痕不静默；subprocess 三件套（capture_output+stdin=DEVNULL+timeout）。
- 每卷门控全绿后**强制回写本 skill**（iteration-protocol.md），禁"用完就走"。
- **双源 sha12 锚定先实测后写死**（az09 实证）：换参脚本 MAP 注入的 sha12 若凭记忆填写，会同时污染 gate ANCHORS / build_front 数据串 / cost_check 文档串，且产物已生成后难以察觉。正确做法：文件就位后先 `sha256sum` 取前 12 位，再回填各锚点；official_wm.pdf 应与用户原始下载件字节级一致（可 `sha256sum` 溯源闭合）。
- **换参后全链 grep 卷名/前缀/短码三类残留**：az09 收尾曾抓到 smoke_front 4 处 sz11 残留（layer:0913:fb 路由/11-10 弹窗/11-1 断言×2/「含 11 章」硬编码）、build_front title「0411」、注释「本册统一 11-」——占位符 token 回填只覆盖数字，卷名/路由/标题类残留必须单独全链扫。

### 坑 42｜mupdf save 随机写 trailer /ID → nowm.pdf 字节漂移（sz02 实证）
