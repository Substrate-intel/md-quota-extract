# 坑全清单（基准卷 lvse 实证，症状→根因→根治→验证四件套）

> 编号 1-11；与姊妹 skill docx-quota-extract 的坑 25-34 同源（提炼自绿色建筑卷 2026-10-15 收官）。

## 一、转换层（阶段 0）

### 坑 1｜pymupdf4llm import 即段错误
- **症状**：`import pymupdf4llm` 段错误（exit 139，1.28.2 layout 引擎）。
- **根因**：布局引擎 C 库与运行环境冲突（pymupdf 本体不受影响）。
- **根治**：转换层用裸 fitz 自研（字号分级 + find_tables）。
- **验证**：269 页全转，md 字节级可复现。

### 坑 2｜旋转水印 redact = 整页抹除
- **症状**：对 ~40° 旋转水印行 bbox 做 redact → 整页内容塌缩。
- **根因**：旋转文本 bbox 是旋转外接矩形，轴对齐化后罩全页。
- **根治**：不 redact；单元格级**行首**孤立 token 剔除 `^([水印字符集])\s`——行首锚定防「基价」等双面字误伤。
- **验证**：水印字符零泄漏进表行；「基 价(元)」等正常术语无损。

### 坑 3｜E-BZ 页码散字：单字符行 + 外侧边 + 分区 offset
- **症状**：页码提取 0 命中或数字倒序（'942'≠'249'）。
- **根因**：西文嵌入字体基线下沉致页码每字符独立成行；位置在**外侧边**（偶页左 x≈50、奇页右 x≈510），居中假设错误；目录区与正文区 offset 不同。
- **根治**：y 带 + 外侧边 x 双条件收集散字，**按 x 左→右重组**（禁 reverse）；offset 分区标定；无页码扉页对排除。
- **验证**：页锚 258/269；扉页对（12/13、66/67…）正确排除。

## 二、md 解析层（阶段 1-2）

### 坑 4｜章标题 `# ` 前缀剥离 → startswith("#") 判界静默全失效
- **症状**：册说明 buf 吞掉 848 段落；所有文本前缀判界静默失效（不报错、产物悄悄错）。
- **根因**：extract_md 产块时剥掉 md 标题前缀存 text，下游沿用文本前缀判界。
- **根治**：块结构显式 `kind:"h1"/"h2"`，**全部边界检查改 kind 判定**。
- **验证**：册说明段落收敛至权威条数；章节区间全对。

### 坑 5｜md 合并单元格形态 ≠ docx 纵向合并
- **症状**：消耗行分类失败（kind 链断裂）；名称行/消耗行混淆；跨列标签留空。
- **根因**：docx 纵向合并读出**每行重复值**，md 合并单元格**只有首格有值**——两种 Office 形态语义不同。
- **根治**：行判别三法——①消耗行=c0 空+前 kind 链式；②名称行=r[1] 无值+r[3:] 非数字文本；③跨列标签 hfill 横向填充；费用行 `"(元)" in joined`；规格/档位行放行。
- **验证**：487 子目 parse_issues=0，人材机消耗行全分类。

### 坑 6｜工作内容/计量单位拆行 → 双遍扫描
- **症状**：430 子目 unit 空（单遍扫到「工作内容」行即 break）。
- **根因**：docx 两者同段，md 拆成独立两行，单遍状态机被先出现的行截断。
- **根治**：unit/work 各扫一遍；分号结尾的「N.」子行是工作内容延续**不 break**。
- **验证**：unit/work 零空（门3 全绿）。

## 三、目录/条文层（阶段 7）

### 坑 7｜目录双栏重组（不经 md）
- **症状**：目录行错配/丢行/页码错挂。
- **根因**：双栏排版全文序输出左右栏交错；md 表格化破坏字符坐标。
- **根治**：从 nowm.pdf 目录页 dict 直接重建——x 分栏 + 栏内 y±6.5 聚类 + 长标题/页码行合并；页码字符坐标是唯一权威。
- **验证**：目录 N 行与正文集合全等、页码单调（门6）。

### 坑 8｜节标题折行污染 sections → 跟表验证
- **症状**：sections 32 个 vs 目录权威 14 个。
- **根因**：说明区长标题折行后恰命中节标题正则。
- **根治**：节标题判定加**跟表验证**（其后 6 块内须有表格）；窗口必须 6 块（4 块漏表距 5 块的案例）。
- **验证**：sections 与目录节行集合全等。

## 四、校验/前端层（阶段 6/9）

### 坑 9｜H1 恒等式项数因卷而异
- **症状**：H1 全卷 fail（曾 487/487 红）。
- **根因**：沿用三项式（基价=人+材+机），本卷实为**四项制含综合费**。
- **根治**：H1 公式**开工前用已知好卷样例校准**；「—」费项按 0 计并留痕；H2 费率带宽按卷实测。
- **验证**：H1 487/487（299 条「—」计 0 留痕）。

### 坑 10｜P1 灵活正则必须作用于未去空白原文
- **症状**：P1 44/487 fail——去空白后相邻编码粘连 '20-920-10'，lookbehind 误杀。
- **根因**：页文本 strip 后相邻子目编码拼接；E-BZ 数字间距又被随机空格拆开——两个方向同时破坏正则。
- **根治**：正则作用于**原始未去空白**页文本：编码 `(?<!\d)前缀-\s*N(?!\d)`、基价 `120[\s.]*78`（E-BZ 空格容忍）。
- **验证**：P1 487/487（对**官方带水印原版**取证——提取用 nowm 干净源、校验用官方原版，双源口径）。

### 坑 11｜前端契约错配致「加载中」假死 + 冒烟必须渲染级
- **症状**：成果库首页永远「加载中…」；文件存在、门控全绿（基线锚的就是错配版）。
- **根因**：两级——①build_front 产出 docx 短键契约 DATA，模板吃 PDF 长键契约（`DATA.stats.h`/`DATA.sections.some` 相继 TypeError，script 整体崩溃）；②冒烟只验文件存在未执行渲染。
- **根治**：①严格按 PDF 长键契约组装 DATA（见 pipeline 阶段 9 契约清单）；②渲染级冒烟机械化（smoke_front.mjs：启动链+13 视图路由真跑）。
- **验证**：冒烟 22/22；端到端字节级一致；九门 9/9。
- **纪律**：前端完成态=渲染级冒烟全绿；门控基线只锚「可复现」不锚「可渲染」。
